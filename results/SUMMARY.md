## 0.1 Errors in the paper's methodology section — fix before camera-ready

Two of the paper's Section IV descriptions contradict the paper's own reported numbers. Both were found by trying to reproduce the numbers from the described procedure, and both are the kind of thing a reviewer can check in minutes.

### (a) The stated label-collapse rule cannot produce the paper's own counts

- **Paper says** — Sec IV-A: 'any utterance whose token-level annotation contains a non-O (non-background) tag is mapped to toxic'
- **That rule actually yields** — 6084 toxic / 2889 non-toxic
- **Paper reports** — 2345 toxic / 6628 non-toxic
- **Rule that does reproduce those counts** — `utterance-level: intentClass != 'O' (E+A+I)`

The paper's stated collapse rule is token-level and contradicts its own counts. The code must have used the utterance-level rule. Section IV-A needs correcting.

### (b) The stated split is arithmetically impossible

- **Paper says** — Sec IV-B: 'approximately 59,820 utterances ... partition it 70/15/15 into train (41,874), validation (8,973), and test (8,973)'
- **Actual corpus** — `CONDA_train.csv` 26,921 rows, `CONDA_valid.csv` 8,974, `CONDA_test.csv` 8,974 (unlabelled); 44,869 rows in total, 35,895 labelled.

A 41,874-row train split is impossible: CONDA_train.csv has 26,921 rows, and the entire corpus is 44,869 rows, not 59,820. However the paper's test split (8,973 rows, 6,628/2,345) matches CONDA_valid.csv exactly, so the actual protocol was almost certainly CONDA_train.csv -> 80/20 -> train/val with CONDA_valid.csv as test (train 21,531 / val 5,383), which is what the surviving memory note records and what this rebuild implements. Section IV-B needs correcting.

CONDA_test.csv is unlabelled (no intentClass), so it cannot have contributed to any scored split.

### (c) DistilBERT's old latency rests on 10× fewer samples

- **Paper says** — Sec III-G: 'DistilBERT uses 100 timed predictions due to its higher per-example cost'
- **This rebuild** — 1000 timed predictions for every model including DistilBERT

Not an error, but the old DistilBERT latency figures rest on 10x fewer samples than the others, so their tail percentiles (p95/p99) are far less stable.

### (d) Figure 4's axis

- **Paper says** — Fig 4 caption: 'Note the log-scale-friendly spread on the x-axis'
- **Observed** — the plotted x-axis is linear (0-80 ms, evenly spaced)
- **This rebuild** — x-axis is genuinely log-scaled

## 2. Label mapping

|---|---|---|---|
| `intentClass in {E}` | 1183 | 7790 | no |
| `intentClass in {A}` | 580 | 8393 | no |
| `intentClass in {I}` | 582 | 8391 | no |
| `intentClass in {E,A}` | 1763 | 7210 | no |
| `intentClass in {E,I}` | 1765 | 7208 | no |
| `intentClass in {A,I}` | 1162 | 7811 | no |
| `intentClass in {E,A,I}` | 2345 | 6628 | **yes** |
| `token-level: slotClasses has T` | 1249 | 7724 | no |
| `token-level: slotClasses has T|C` | 2406 | 6567 | no |
| `token-level: slotClasses has T|D` | 1539 | 7434 | no |
| `token-level: slotClasses has T|D|S` | 3846 | 5127 | no |
| `intentClass != O  OR  slot has T` | 2589 | 6384 | no |
| `intentClass != O  AND  slot has T` | 1005 | 7968 | no |

**Adopted:** `toxic = 1 if intentClass != 'O' else 0`

One row (`Id` 2525, class `O`) has a blank utterance and is dropped, which is what turns 8,974 raw rows into 8,973.

### 2.1 Caveat on the `A` class — read before citing

CONDA's own README treats only `E` (explicit) and `I` (implicit) as toxicity classes. `A` is an **action** class: utterances asking others to *report* or *commend* a player. The adopted mapping labels all 580 `A` utterances toxic, of which 75 contain "commend"/"comment" — positive messages. Token-level evidence agrees that `A` is not toxic:

| intent class | n (test) | share carrying a token-level `T` tag |
|---|---|---|
| `E` explicit | 1,183 | 80.6% |
| `I` implicit | 582 | 4.0% |
| `A` action | 580 | **5.0%** |
| `O` neutral | 6,628 | 3.7% |

`A` behaves like the neutral class, not like `E`. Including it inflates the toxic class by 33% (580 / 1,765) with largely non-toxic content.

**The paper already noticed this**, in Sec V-F: *"The high toxic-class weight on report and commend reveals an annotation artifact worth flagging: utterances calling on others to report a teammate are themselves frequently labeled toxic, so the model partially encodes the social act of group reporting rather than only lexical content."* What the paper treats as an interesting quirk of the LR coefficients is in fact a property of the label definition itself, affecting 580 test utterances — a quarter of the positive class. The sensitivity analysis in §11 is what turns that observation into a quantified threat-to-validity. The mapping is kept as the primary one because it is the one that reproduces the original counts, but every split also carries a `label_EI` column (`toxic = intentClass ∈ {E, I}`) so the sensitivity analysis can be run without re-deriving anything.

## 4. Preprocessing

Classical pipeline order:

1. lowercase
2. strip_urls_mentions ([SEPA], @mentions, URLs)
3. leetspeak (3->e 0->o 4->a 1->i @->a $->s)
4. strip_punctuation (REPLACED BY SPACE; apostrophes kept inside words only)
5. remove_stopwords (NLTK english minus gaming whitelist)
6. porter_stem

DistilBERT receives only: lowercase, strip_urls_mentions.

**Punctuation policy: `replaced_by_space`.** Punctuation is replaced by a space rather than deleted. This avoids welding words together, but means the character-insertion attack is NOT repaired by preprocessing ('f.u.c.k' -> 'f u c k'). Deleting punctuation would accidentally defend against that attack; see the script 06 ablation.

**The gaming stopword whitelist is a no-op.** None of `['buff', 'ez', 'gg', 'gl', 'glhf', 'hf', 'nerf', 'noob', 'op', 'wp']` appears in NLTK's English stopword list, so the effective stopword count is 198 either way. Reported rather than silently dropped.

## 7. Adversarial robustness

**Threat model.** Attacks applied to RAW toxic utterances, then passed through each model's normal preprocessing. Non-toxic rows untouched; macro-F1 computed over the full test set.

Candidate-token rule: CONDA token-level slot tag in {T, C} when the annotation aligns with the tokens; otherwise alphabetic, len>=3, non-stopword.

| attack | definition |
|---|---|
| `leetspeak` | per char of candidate tokens, p=0.5: a->4 e->3 i->1 o->0 s->$ t->7 |
| `char_insert` | random punctuation from '.-_*`~^' between internal characters |
| `whitespace` | space between internal characters |
| `swap` | one adjacent transposition per candidate token |
